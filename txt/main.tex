\section{Introduction}

Prime editing is a state of the art gene editing technology that allows for precise and versatile editing of the genome of various species, including human\cite{liudavidr.SearchreplaceGenomeEditing2019, }. It is more versatile than base editing that can only perform single base substitutions, and more precise than CRISPR-Cas9 that is prone to off-target effects due to the double strand break required for the editing\cite{kantorCRISPRCas9DNABaseEditing2020}.

However, as the number of studies involving prime editing increases, comparing the benchmarking new deep learning systems becomes more difficult. Having encountered this issue during the development of my own prime editing guide design system, I implemented a central database hosting prime editing experiemental data. This database, named PE DB, is designed to store and retrieve prime editing experiemental data, including the guide RNA sequences, the target DNA sequences, and the editing outcomes.

\subsection{Data Augmentation}

A major problem with the datasets is how the editing efficiency is defined. The most straitghtforward definition uses the total read count of the successfully edited sequences divided by the total read count of the sequences\cite{schwankgeraldPredictingPrimeEditing2023}. However, the augmented measure deducting the background editing rate from the total editing rate is more common in computational studies\cite{kimPredictingEfficiencyPrime2021,yuPredictionEfficienciesDiverse2023,mathisMachineLearningPrediction2024}. 

In addition to the raw data, a number of frequently used features are also precalculated and stored in the database to aid rapid development of new machine learning systems, which often use these features to form part of the input data\cite{yuPredictionEfficienciesDiverse2023,mathisMachineLearningPrediction2024,schwankgeraldPredictingPrimeEditing2023}

\subsection{Data Storage}

Primary key access is significantly more efficient than indexing with secondary keys, especially when the database is large. 

However, join queries are extremely slow on large datasets since Cartesian products are generated in the process. To avoid this, the column propagation method is used in the design of the hierarchical database.

\subsection{Data Retrieval and Interaction}

The database is designed to be accessed via a RESTful API, which allows users to query the database using a variety of parameters, such as date of publication, editing type, study type, and more. The resulted data is returned in a compressed CSV format, which can be easily imported into most machine learning systems.

Additionally, for easier benchmarking of new machine learning systems with existing state of the art models, the database also provides the options to export the data with features required by top performing models, such Deep Prime by Yu et al.\cite{yuPredictionEfficienciesDiverse2023}.
